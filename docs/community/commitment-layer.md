# 承诺层方案（区块链存证 · 公开备选）

> 三层治理理念的第三层方案文档，随本仓库公开。前两层（运营层、记录层）已落地；本层**方案公开、暂不实施**——若有很多群友明确要求，照此开工，不需要重新讨论。

## 一、定位与沿革

**要解决的问题**：向群友表达公平——群主也不能说改群规就立马改群规。即修规程序正义：群规可以迭代，但「改」这个动作要走流程、有公示期，且这套程序对群主自己的约束要让群友看得见、信得过。这在机制设计里叫**承诺装置（commitment device）**：群主主动把自己的权力关进笼子，公开表态。

**决策沿革**：

- 2026-08-25 ~ 08-27 四轮讨论收敛出完整技术方案；08-27 曾裁定「暂缓 + 存档保密」，理由是群友大概率不关心存证细节。
- 2026-08-28 群主裁定反转：**方案不用藏着，要公开**。三层运营理念对群友整体公开——既是社群特色，也让群友知道有承诺层这个备选项；**藏着的话没人知道，相当于没有**。启用条件相应改为呼声驱动：先实现前两层，最后这层备选让群友知晓，**有很多群友明确要求做时即可开始考虑**。

## 二、三层结构（前两层已落地，本方案是第三层）

| 层 | 载体 | 作用 | 状态 |
|---|---|---|---|
| 运营层 | 群公告 `announcement.txt` 里的「群规修订程序」条款（7 天公示） | 公平感的主要来源——白纸黑字的程序承诺 | ✅ 已落地 |
| 记录层 | GitHub 公开仓库 + Release 发版（`announcement-vX.Y.Z` tag） | 每次修订有公开时间戳的版本历史，群友点链接就能看 | ✅ 已落地 |
| 承诺层 | 链上存证（timelock 合约 / 哈希锚定）+ 零门槛验证页 | 「群主想改也得等 7 天」的硬承诺，程序代码保证 | 📋 公开备选（本文档） |

## 三、技术设计（启动时照此实施）

### 方案 A：哈希锚定（轻量）

把 `announcement.txt` 每个版本算一个哈希值（指纹），写进一笔链上交易（Base / Arbitrum 等 Layer 2，单次几美分）。文本改一个字，指纹就对不上——证明「从锚定时刻起内容未变」。

**补锚的效力边界（重要）**：事后补做锚定，链上时间戳是「补做时刻」，**证明不了「当时就是这个内容」**。若在意「从 v1.0.0 起就有强时间戳」，需在版本发布当下就锚定；启动承诺层后从「当时的现行版」开始锚，只能保证此后不可篡改。

### 方案 B：timelock 合约 + 验证页（完整）

原理极简：

1. 合约里存「现行群规版本的哈希值」；
2. 任何人（包括群主）想修订，调用 `propose(新版本哈希)`，合约自动进入 7 天公示期；
3. 期满后调用 `finalize()`，现行版本指针才切换。

7 天延迟是**代码强制**的——群主自己部署的合约，自己同样绕不过。成本：Layer 2 部署 1 美元以内，每次修订 propose + finalize 合计几美分。**必须配套零门槛验证网页**（GitHub Pages 静态页即可）：群友点开看到人话——「现行群规：vX（X 日生效）｜最新修订提案：vY，公示期至 Z 日」——链的细节全部藏在页面背后，入口出现在群公告里，不要求群友会用区块浏览器。

**更重的可选形态**：合约升级为 2/3 多签（群主 + 两位群友代表共同签名才能 finalize）——参与感强但门槛高（群友代表要有钱包、承担人情负担），建议群运营有信任基础后再考虑。

## 四、关键边界（宣传与较真时的立身之本）

- **链锁的是记录，锁不住微信**：技术上群主仍可能链外先斩后奏（链上指针还在 vX、行为却按 vY 办事），但这必然留下可指证的违约铁证。**技术提供的是「违约必留痕、不可抵赖」，不是「违约不可能」**。
- 因此宣传口径必须说「**违约必留痕、可查证**」级别的表述（存证、留痕、可查证），**不说「绝对不可篡改」「群主绝对改不了」**——后者一旦发生一次链外违规，整套承诺的宣传反噬信誉。
- **信任链的根不是技术**：「公告里的链接指向哪」这个入口本身在群主手里，纯技术根除不了极端威胁；技术层只是把脚印踩得更深。根仍是群主的日常行为 + 群友的持续观察。

## 五、对群友的表述口径

- **理念现在就公开**：三层治理理念整体写进群公告（前两层已落地、承诺层公开备选、群友呼声可启动）——公开本身就是特色，也是备选项能被「要求」的前提。
- **用什么词**：「区块链存证」——大众语境成熟词（司法存证 / 版权存证），一听就懂。**不用**「智能合约」「timelock」等开发者词汇（那些只出现在本文档这类技术页里，群公告与群聊不用）。
- **群公告与群聊中不出现的词**：代币、gas、钱包、私钥、合约地址、交易所——引向虚拟货币联想（微信生态对此敏感），且暴露无谓的实操门槛。
- **启动后的绑定**：链上层和验证页**先做完、做得能打，再挂到群公告**——宣传出去的链接经不起点击是最糟的局面；此后每次修订生效公告顺带一句「已上链存证」，不在群聊里反复吆喝。

## 六、启动条件（2026-08-28 修订为呼声驱动）

**核心条件**：**有很多群友明确要求做这一层**——达到一定数量即可开始考虑启动（方案已公开，群友知道它的存在，要求才有落点）。

**辅助信号**（出现时主动评估，与核心条件任一成立即可提上日程）：

1. 群里发生过一次真实的改规争议（有人较真了）；
2. 群规模明显扩大、成员流动加快（如超百人）；
3. 出现了爱较真的核心群友。

在此之前它是零收益的维护负担（每次改版多走流程、惦记验证页存活）。

## 七、启动步骤（概要）

1. 选定 Layer 2 网络，准备钱包（gas 成本控制在个位数美元）；
2. 先做方案 A（哈希锚定当期现行版），验证页用 GitHub Pages 静态页；
3. 若需要「想改也得等 7 天」的硬承诺，再上方案 B（timelock 合约）；
4. 验证页能打之后，群公告加入常驻声明一句 + 链接；
5. 之后每次修订：propose（或锚定新版本哈希）→ 公示 → finalize，生效公告顺带提及存证。

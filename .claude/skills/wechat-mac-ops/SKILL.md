# 微信 Mac 客户端操作（社群运营动作）

用电脑操作能力在本机微信 Mac 客户端上，完成必须由群主账号手动点的三个核心动作：**改群名称、编辑并发布群公告、在群里发言**。

本 skill 来自 2026-10-02 一次完整的真实操作（当天把群名改成「AI+X 实战经验交流群」、把群公告发布为 v1.2.0、并在群里发了一条自我介绍）。当天踩过的坑都写在下面，照这个流程做可以一次成功。

## 什么时候用

- 用户要求在本机微信客户端里动手：改群名、改/发群公告、在群里发消息、改群设置、拉人建群等
- 用户的措辞可能是「你直接改一下」「帮我操作微信」「用电脑操作能力实现」——这类请求就是要走本 skill，不要推回给用户手动做
- 排查类：点了没反应、坐标点偏了、弹窗怎么点都不中、找不到微信窗口

不适用：与微信无关的 GUI 操作；公域平台投放（那是 GrowthMarketerAgent 的职责）。

## 前置条件

1. **macOS + 微信 Mac 4.x**，已登录。若启动后停在「进入微信」登录页，点一下该按钮即可进入，**不需要扫码**（登录态已保存）
2. **open-computer-use 可用**：`open-computer-use doctor` 应输出 `accessibility=granted, screenRecording=granted`；缺权限时按提示到「系统设置 → 隐私与安全性 → 辅助功能 / 屏幕录制」授权
3. **窗口几何与缩放每次现查**，不要凭记忆写死坐标——`scripts/wxgeom.py geom` 会打印当前微信窗口的位置、尺寸和「截图像素 → 屏幕点」的换算比例

## 统一机制：三条命令 + 一个坐标约定

**所有动作都通过 `open-computer-use` 的命令行**（脚本 `ocu.sh` / `tap.sh` / `clic.sh` 已封装）。为什么不走 MCP 的 computer-use 工具：MCP 那条路每一步都要人工点「批准」，一条龙操作会被打断几十次；命令行直连不经过审批层，全程无弹窗。

| 要做什么 | 怎么做 |
|---|---|
| 看当前界面 | `scripts/ocu.sh get_app_state '{"app":"WeChat"}'` → 打印无障碍元素树，并把截图存到 `ocu-shot.png` |
| 点击（真点击，不移动鼠标） | `scripts/clic.sh <截图x> <截图y>` |
| 点击（拖拽式，会移动真实鼠标指针） | `scripts/tap.sh <截图x> <截图y>` |
| 按键 / 快捷键 | `open-computer-use call press_key --args '{"app":"WeChat","key":"super+f"}'`（`super` = ⌘，例：`super+v`、`Return`、`Escape`、`Tab`、`space`） |
| 输入文字 | **不要用 type_text**（微信的自绘输入框收不到）——把文字写进剪贴板，再按 ⌘V 粘贴 |

**坐标约定**：一律用**截图里的像素坐标**。先用 `ocu.sh get_app_state` 拿到截图，量出目标位置，把坐标交给 `clic.sh` / `tap.sh`——它们内部会让工具做「截图像素 → 窗口点 → 全局点」换算。主窗口的换算稳定可用；**独立的弹窗/对话框另有规则，见「坑 1」**。

## 任务 1：改群名称

1. **打开目标群**：⌘F 聚焦搜索框 → 把群名写进剪贴板 → ⌘V 粘贴 → 按 `Return` 打开会话
   （先用 `pbpaste` 确认搜索词是**群当前的名字**，改名前和改名后用词不一样）
2. **打开群信息面板**：点群聊右上角的「···」按钮（截图坐标约在宽 94%、高 4% 处，按当前截图尺寸换算；精确比例与识别特征见 `references/wechat-ui.md`）
3. **进入名称编辑**：在右侧面板里点「群聊名称」那一行（值就是当前群名）——点击后该行会变成**可编辑文本框**
4. **替换文字**：⌘A 全选 → 把新群名写入剪贴板 → ⌘V 粘贴
5. **提交**：按 `Return` → 弹出确认框「修改群聊名称?」→ 点「**修改**」（右侧绿色按钮）
6. **验证**：截图确认三处都变了——群聊标题（形如 `新群名 (人数)`）、左侧会话列表那一行、信息面板「群聊名称」字段

要点：
- **改群名会在群里产生系统提示**（「你修改群名为…」），**全体群成员可见**。动手前确认这就是用户要的；群里人多时值得先提醒一句
- 第 5 步的确认框是独立弹窗，点击坐标要用它自己的窗口尺寸反推（见「坑 1」），不要沿用主窗口的比例

## 任务 2：改群公告

1. **打开目标群** → 点「···」进信息面板（同任务 1 第 1–2 步）
2. **打开群公告窗口**：点面板中段的「群公告」那一行（行内会显示当前公告的预览文字，如「【群名称】…」）→ 弹出一个独立窗口，标题是「"群名"的群公告」
3. **进编辑态**：点该窗口右上角的「**编辑群公告**」按钮 → 变成编辑器（顶部有排版工具条 + 右上角绿色「完成」按钮）
4. **替换正文**：⌘A 全选 → 把新公告全文写入剪贴板 → ⌘V 粘贴（正文通常是项目里的 `docs/community/announcement.txt`，含版本脚注与归档链接）
5. **提交**：点「**完成**」（右上角绿色按钮）→ 弹出确认框「**发布此公告会通知全部群成员**」→ 点「**发布**」（绿色按钮）
6. **验证**：信息面板的「群公告」预览应显示新正文开头；再点进群公告窗口核对正文与尾部版本脚注（长文本可先用 `scroll` 工具滚到底，或按需放大窗口）

要点：
- **发布 = 通知全部群成员**（红点 + 系统提示）。这是微信的行为，只有用户明确要发才发
- 若误触了窗口的关闭动作，会出现「**关闭将不会保留本次编辑的内容**」确认框，选「**继续编辑**」就能保住刚粘贴的内容重来（别选「关闭」）
- 公告正文务必与仓库里的 `announcement.txt` 一致（版本脚注是给群友查证用的，别漏）

## 任务 3：在群里发言

1. **打开目标群**（同任务 1 第 1 步）
2. **聚焦输入框**：在聊天区底部的消息输入框上点一下（聚焦后：占位文字消失、右下角出现「发送」按钮）
3. **贴文字**：把要发的内容写进剪贴板 → ⌘V（多行文本整段贴入，换行都保留）
4. **发送**：按 `Return`（微信默认回车发送）
5. **验证**：气泡出现在聊天区、输入框回到空状态（占位文字恢复）

要点：
- **发送前一定核对目标会话**：微信没有二次确认，发错群是公开事故。发送前截图确认标题栏是目标群
- **发送前备份剪贴板、发送后恢复**（见「收尾」）
- 内容要「拿来即发」：群主账号发出的消息带着群主的身份，措辞按用户要求来，拿不准就先给用户看草稿

## 收尾（每次都做）

1. **恢复剪贴板**：改前 `pbpaste > /tmp/wx-clip.bak`，改后 `pbcopy < /tmp/wx-clip.bak`
2. **清理截图**：操作过程中截的图含群成员头像、聊天内容等隐私，收尾时删掉（别留在会进 git 的目录；临时文件放项目 `tmp/` 或 `/tmp`）
3. **汇报影响面**：明确说明这次操作在群里产生了什么可见变化（改群名 / 发公告的**全体成员通知**、发送的消息内容原文）

## 坑清单（第一次做必读，详述见 references/）

1. **弹窗（确认框）要用它自己的窗口尺寸反推坐标**——弹窗是独立窗口，工具的换算比例与主窗口不同，直接照主窗口的比例点，会点到旁边去。做法：用 Quartz 列出微信所有窗口找到弹窗的 bounds，按「全局点 = 弹窗原点 + 截图坐标 × (弹窗尺寸 ÷ 截图尺寸)」换算。**判断标准**：点完没反应、或者关掉/取消了本来不该动的弹窗，就是这个坑
2. **有的按钮 `clic.sh` 点不中，有的按钮 `tap.sh` 点不中**——`clic.sh` 走「无障碍元素优先」的路径，遇到自绘控件可能在窗口层面被吞掉；`tap.sh` 是真实鼠标事件（会移动指针），但连续拖拽事件会被某些控件当成拖拽而非点击。**两个都试**，哪个体现在截图上出现就继续用哪个
3. **`type_text` 对微信无效**——一律用剪贴板 + ⌘V
4. **键盘快捷键是可靠的**：⌘F（搜索）、⌘A / ⌘V、`Return`、`Escape`（取消当前弹窗）、`Tab`（切换焦点）都能穿过微信的自绘界面
5. **窗口尺寸会变**：会话列表滚动、面板内容变化都会让同一行控件的位置漂移几十像素——每次点击前重新截图定位，不要复用上次的坐标
6. **操作会改变状态**：改群名会让群名、会话列表、面板同时刷新（面板里各行的位置随之上下移动）；找不到行时先重截一张图再量

## 文件说明

- `scripts/ocu.sh` —— 调 `get_app_state` / 任意工具，打印元素树并保存截图（`ocu-shot.png`）
- `scripts/tap.sh` —— 拖拽式点击（含全局指针兜底环境变量，会移动真实鼠标）
- `scripts/clic.sh` —— 真点击（`click` 工具 + 全局指针兜底）
- `scripts/wxgeom.py` —— 打印微信窗口几何；`conv` 子命令把截图坐标换算成屏幕点坐标（例：`python3 wxgeom.py conv 1280 1090 1210 45 --name 微信`；弹窗则直接给弹窗 bounds），`cursor` 子命令回读鼠标指针位置——排查坐标偏移时用
- `references/computer-use.md` —— open-computer-use 的工作机制、坐标换算细节、审批与逃生开关（想弄清「为什么点偏了」时读）
- `references/wechat-ui.md` —— 微信 Mac 4.x 的界面地图：各窗口结构、主要控件在截图中的大致位置与识别特征
